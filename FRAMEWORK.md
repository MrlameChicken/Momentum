# Momentum — Daily Operating Guide

Your goal: **deliver reliably, understand what you build, and make steady progress without filling every minute with work.**

Use the Momentum app: https://mrlamechicken.github.io/Momentum/

## The daily loop

**PLAN → EXECUTE → VERIFY → CLOSE**

### Morning — Plan (5 minutes)

Open **Today**.

1. **Today's priority:** Write one important *result*, not a vague activity.
2. **First step:** Write something you can start within five minutes.
3. **Define done** (optional): Write evidence that proves the result worked.
4. Add **one or two optional tasks** only if really needed.

Example:

- **Priority:** Run one code-index evaluation on my own and understand the output.
- **First step:** Open the repo, find the sample command, and execute it.
- **Done looks like:** A run completed, output inspected, input → checks → judgment → result explained.

Prioritize based on work commitments and risk. An urgent blocker or stakeholder deliverable beats another nice-to-have feature.

### During work — Execute (25–50 minutes)

1. Start a **25- or 50-minute focus timer**. Try to protect one session most working days.
2. Perform the first step immediately. Keep optional research, messages, and other tabs out of that block.
3. When distracted, return to **one physical action**. If needed, use a five-minute start.
4. When blocked, write down the exact error or missing fact and investigate *that*.

The focus timer is a tool, not a score. The aim is useful outcomes, not maximum minutes.

### Before marking Done — Verify

For AI-assisted engineering, follow **Specify → Delegate → Run → Explain**.

Before checking off your priority, ask:

- Did I run or test it myself?
- Did I inspect actual output rather than accept an AI summary?
- Can I explain the main flow and decisions?
- What remains broken or uncertain?

If not finished, note the next step. Honest progress is more useful than a premature checkbox.

### End of work — Close (3 minutes)

Open **Close out the day**.

- **What did you finish or verify?** Write observable evidence.
- **Where will you start tomorrow?** Write one exact next action.
- Tap **Finish for today**.

Then step away from work wherever possible. A clear restart point prevents rumination.

### Once a week — Review (15 minutes)

Open **Week**.

- Notice completed priorities, time spent focusing, and days closed.
- Write one adjustment: **What would make important work easier next week?**
- Change one thing at a time; don't redesign your entire routine.

## The principles

1. **One important result a day.** Everything else is optional or scheduled around actual responsibilities.
2. **Start small and specifically.** Decide the first action before the resistance arrives.
3. **Verify instead of just generating.** Using AI quickly is valuable only when you own the outcome.
4. **Consistency beats intensity.** If a day goes sideways, begin again the next opportunity.
5. **Recovery is part of execution.** Sleep, exercise, family, and leisure don't need to be justified as productivity.

## When plans break

- **Urgent work arrived:** Change today's priority to reflect real commitments.
- **No time for a full session:** Do a five-minute start and record the next step.
- **Task was too large:** Shrink the definition of done to one testable milestone.
- **Missed a day:** Do not manufacture a streak or make up hours. Resume.
- **Need to get ahead:** Use protected time for understanding and reducing future technical risk—not merely generating more features.

## Why this works

The workflow draws on established research on **specific goals with feedback** (Locke & Latham), **implementation intentions / if–then plans** (Gollwitzer & Sheeran), **procrastination and short-term mood regulation** (Sirois & Pychyl), and **retrieval practice and durable learning** (Dunlosky et al.). The exact minute allocations are practical starting points, not scientifically established universal prescriptions.

**The one question to remember:** *What's the next concrete action that produces an observable result?*
